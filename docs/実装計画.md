# Jarvis｜個人の相棒AI 実装計画・使用仕様

## どんな時に使うか

仕事の状況を短く書き、資料のレビュー観点や今日の一手を整理するための個人用ワークスペース。利用者の過去の作業から、資料の根拠を確かめること、未確定事項と決定を区別すること、相手に伝わる形にまとめることを用途に選んだ。参照画像は存在しないため、UIは新規設計とする。

## 操作方法とインターフェース

| 画面 | 操作 | 結果 |
| --- | --- | --- |
| 親ポータル | 利用する版を選ぶ | 選択した版の会話画面へ移動する |
| 会話 | 候補から目的を選ぶか、相談を直接入力して送信 | 初期状態では端末内のルールで相談を整理し、次に考える観点を返す |
| 端末内AI | モデルを明示的に読み込み、相談を送る | 対応端末ではWebGPUでモデルを実行し、会話と自分用の文脈メモを使って文章を生成する |
| 文脈と履歴 | 前提を書き、必要に応じて端末保存を選ぶ | 再入力を減らす。共有PCでは保存を使わず、利用後に履歴を消せる |
| 表示 | Light・Dark・Auto のいずれかを選ぶ | 全画面で同じ設定を使う。Auto は開いたままOSの配色変更に追従する |
| ORIGAMI版 | 観測と仮説を分けて記入し、小さな試行か保留を選ぶ | 結果・理由を追記して判断を選び直せる。経緯を会話に持ち込める |

## 構成とデータの扱い

GitHub Pagesで配信する静的サイト。親ポータルの相対パスは ./、初版は ./v1/、第2版は ./v2/。各版は独立した資産で動作する。推論時に利用者の相談をサーバーへ送る仕組みは設けず、対応ブラウザ上でモデルを実行する。初回モデル取得には回線、空き容量、対応GPUが必要。モデルが使えない場合もルールによる整理は利用できる。Driveの内容は設計時の参考に使い、原文、業務データ、個人履歴を公開サイトへ同梱しない。

## レビューと公開手順

1. 操作ごとに開始状態、入力、結果を確認する。架空の入力で会話、任意保存、テーマ、キーボード操作を検証する。
2. 認証済みの kentaro-oishi-c3creators に新規リポジトリ jarvis-companion を作成。初版と親ポータルをGitHub Pagesに公開し、公開ページの読み込みと操作を確認する。
3. 個人Driveで確認したORIGAMIの原則を使い、事実・仮説・試行・保留・再判断の履歴を第2版に実装する。
4. 両版を案内する親ポータルを再公開する。公開URLで各版に直接アクセスし、相談、画面遷移、テーマ変更を試す。第2版で記録を作成し、判断の追記と会話への取り込みを検証する。
5. 初版配備時と再配備時に初版の資産を比較し、公開コミットを記録する。
